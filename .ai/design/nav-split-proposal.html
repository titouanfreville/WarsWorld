Custom

Custom lobbies are unranked by design — your rules, no ladder impact.

What this needs from the backend.
  • matchmaking.join takes mode: z.literal("1v1") — FFA/2v2 need it widened to an enum.
  • No ranked axis on join, so Ranked Std and Std are the same queue today.
  • Queue population ("14 in queue") isn't exposed — I'd cut it for v1 rather than fake it.
  • Rating engine swaps from plain Elo (elo.ts, K=32, start 800) to OpenSkill (openskill@5.0.1, MIT). MMR re-keys from (leagueType, playerId) to (playerId, mode) and stores μ/σ.
Decided: the flat LeagueType enum decomposes into mode × ruleset; broken survives as a ruleset, dualLeague is parked. Hidden rating is per-mode, never sent to the client; the ladder (rank/division/LP) is what's displayed.
The ladder — four active ranks, five divisions each (V→I), 100 Military Merit per division. Percentile bands, so they stay meaningful as the playerbase grows. Cadet is placements only; Maréchal is the apex (no divisions, Merit unbounded, so the top of the ladder still sorts). The full enum ships dormant — Sergeant, Major and Colonel activate at a season rollover, never mid-season.
Cadet · placements Private V–I · 40% Lieutenant V–I · 35% Captain V–I · 20% Maréchal · top 5%

Ranks stay English (the UI is English); Maréchal is French because it reads as a title, matching MEDAILLE_MILITAIRE / CROIX_DE_GUERRE — proper-noun decorations, not translated common nouns. Enum is ASCII (marechal), display is accented — the same split those medals already use.

  • Why not Recruit — taken. It's honor's pre-Bronze tier (honor.ts:17). Cadet is clean, and Will starts DoR as one.
  • Why not letters — canon AW "ranks" ARE S/A/B/C (War Room, over Speed/Power/ Technique), and computeGrades() already uses them for the per-match grade.
  • Why not metals — HonorInsignia owns bronze→diamond. Both badges can show side by side, so the ladder takes military titles + a green→orange ramp instead.
  • Military Merit, shown as Merit — not "MH": honor is an existing prestige track (opponents award medals → Bronze…Diamond → Prestige), so "Military Honor" would collide head-on. Honor is given by your opponent for conduct; Merit is earned by winning.
  • Never abbreviated to "MM" — one letter from MMR, the hidden rating in this same system (12 files; mmrDiff ships in the queue event). "MM gains scale with MMR" is unreadable, and mm beside mmr in code is a bug waiting to happen. "MM" also just reads as matchmaking.
  • Why spelled out at all — every short code is taken: CP (capture points AND CO power), MP (movement), HP, SP (star/super power).
honor.ts:4 already says it: "Honor = a PRESTIGE track (distinct from the military-rank ladder, which is MMR)" — this ladder is that sentence's other half.

Where these stats come from. Grade, damage, kills, captures and duration are already computed — endgame.summary replays the event log and returns computeGrades() (Tactics/Strength/Economy → S/A/B/C) plus damageDealt, unitsKilled, captures, durationMs, fog, isRanked. Public by design, so it survives archival.
  • Perf: summary replays the whole log per match — rows fetch it lazily on expand; the collapsed line uses the cheap list query.
  • Missing: per-match MMR delta isn't stored (only current + top). Needs an MMR history row, or the column gets dropped.
